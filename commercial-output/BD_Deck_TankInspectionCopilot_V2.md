# Tank Inspection Copilot — Business Development Deck V2

## Positioning

Tank Inspection Copilot is a structured inspection workflow for aboveground storage tank inspections.  
It connects field capture, findings, photos, location, MFL context, review, and export into one guided process.

This version of the deck focuses on:

- workflow comparison
- visible pain points in the current process
- the proposed future workflow
- the value of the final inspection package

---

## Slide 1 — Cover

**Title:** Tank Inspection Copilot  
**Subtitle:** From field inspection workflow to structured inspection package

Core message:

> Capture readings, findings, photos, location, and MFL context in one guided flow — then leave site with a report-ready output package.

---

## Slide 2 — Current Inspection Workflow

**Title:** Current inspection workflow

Workflow:
1. Field inspection
2. Separate records
3. Back-office re-keying
4. Rebuild context
5. Merge MFL separately
6. Final QA and report

Pain points to highlight:

- duplicate entry
- broken links between UT, findings, and photos
- weak location traceability
- fragmented outputs

Core message:

> Today, the inspection and the report are still two different workflows.

---

## Slide 3 — Proposed Workflow

**Title:** One guided flow from inspection to output

Workflow:
1. Configure tank
2. Run task-driven capture
3. Capture findings in context
4. Link location and evidence
5. Review on site
6. Export structured package

Solution themes:

- single capture path
- evidence linked at source
- standard output structure

Core message:

> The customer is not buying another inspection form. They are buying a cleaner workflow and a better inspection package at the end.

---

## Slide 4 — Guided Task Workflow

**Title:** Guided task-driven workflow

Points:

- configure once
- scope selection
- task board with progress and warnings
- draft save and resume

Core message:

> The app guides the inspection sequence so less is left to memory.

## Slide 5 — Structured UT Data Capture

**Title:** Structured UT data capture

Show that each surface feeds a known output:

- Shell UT → shell thickness table
- Roof UT → roof thickness table
- Shell nozzles → shell nozzle table
- Roof nozzles → roof nozzle table
- Bottom MFL → MFL section

Core message:

> Each task captures readings in the same structure the report needs later.

---

## Slide 6 — In-Context Finding Capture

**Title:** In-context finding capture

Flow:
1. Photo
2. Annotate
3. Type and severity
4. Location
5. Measurements
6. Save

Core message:

> Findings are documented inside the active task, not reconstructed later from memory.

---

## Slide 7 — Location Intelligence by Surface

**Title:** Location intelligence by surface

Surface logic:

- Shell: coarse UT + optional precise shell mapping
- Roof: ring / section / plate-based coarse layout
- Shell nozzles: course + degree on unwrapped shell
- Roof nozzles: roof map registration before readings

Core message:

> The app uses the right level of mapping for each surface instead of forcing one location model everywhere.
